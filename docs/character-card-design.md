# 写作用角色卡（Character Card）改造设计文档

> 状态：已评审定稿，实施中（8 项决策见第九节）
> 目标：保留 CSP 现有「研究 → 蒸馏」管线不动，把最终产物从「可执行的角色扮演 Skill（SKILL.md）」改为「写作用角色卡（Character Card）」——供 AI 辅助写作时作为参考规范引用，让 AI 以**作者/叙述者**的视角写出符合角色行为逻辑的场景、对白和内心戏，并进一步用于**场景设计、剧本设计**，让 AI 设计的剧情、场景不至于 OOC。
> 触发背景：现有产物的语言、结构和质量检查全部面向「角色扮演」（第一人称、`用「我」`、退出触发、口语优先），当用户用 CSP 辅助**同人写作**时，产物提供的规则是「扮演角色去说话」，而非「以作者身份正确地写这个角色」。管线产出的行为蒸馏本身可直接复用，需要改造的是最终产物的组装视角、模板和验证方式。此外，写作需求不止「逐句落笔」，还包含**先把剧情/场景/对白框架设计出来**再填充——设计阶段的 OOC 往往源于「作者先定情节、再让角色配合」，角色卡需要同时约束「怎么写」和「怎么设计」。

---

## 一、背景与目标

### 1.1 现状

当前 CSP 的最终产物 `SKILL.md` 是一份**可执行的角色扮演指令**：

- 开篇即要求「**此 Skill 激活后，直接以[角色名]的身份回应**」；
- 语言匹配、第一人称、退出触发、口语优先；
- 行为示例描述「角色会说什么、做什么」；
- 资料边界用角色口吻回应（「我的资料更新至…」）。

这套产物面向「角色聊天 / 扮演 agent」，在写作场景下会产生三种问题：

1. **视角错位**：写作 AI 需要的是「作者/叙述者」视角，而不是「角色本人」视角。它不能只说角色的台词，还要写角色的动作、场景、第三人称叙述、以及「角色心里在想但没说出口的话」。
2. **内容缺口**：现有模板没有「内心戏怎么写」「叙述者能知道多少」「何时进入角色内心、何时退出」的规则；也没有「把行为规范落成一段场景文字」的写作示范。
3. **设计阶段无约束**：现有产物只管「写出来」，不管「怎么设计」。当 AI 被要求「设计一个剧情 / 一个场景 / 一集剧本」时，它倾向从情节出发倒推角色行为，导致角色为剧情服务而 OOC——角色卡需要覆盖**场景设计、剧本设计**阶段，提供设计规则与反 OOC 校验机制。

### 1.2 本次改造目标

1. **最终产物改为「写作用角色卡」**：一份供写作 AI 引用的参考规范，覆盖角色在场景中的行为、对白、内心戏与社会认知。
2. **视角从「扮演角色」改为「作者/叙述者」**：产物指令的对象是写作 AI，不是角色本人。
3. **研究→蒸馏管线原样保留**：Phase 0–7、五条研究线、`sources.json`、`distillation.md`、`merge_research.py`、跨媒体覆盖全部不变；行为蒸馏成果直接复用到角色卡中。
4. **支持场景设计、剧本设计**：角色卡提供「场景与剧情设计规范」和「反 OOC 检查清单」，让 AI 设计的剧情、场景、对白框架在落笔前就与角色行为逻辑对齐。
5. **质量验证同步调整**：`quality_check.py` 的检查项从「角色扮演规则」改为「写作视角规则 + 角色卡结构 + 设计/OOC 校验要素」。
6. **可追溯、可更新不变**：资料日期、诚实边界、来源链、更新回应规则全部保留，仅改为作者视角措辞。

## 三、核心转变

| 维度 | 现状（角色扮演 Skill） | 改造后（写作用角色卡） |
|---|---|---|
| 产物本质 | 可执行行为程序 | 可引用的写作参考规范 |
| 指令对象 | 扮演 agent（角色本人） | 写作 AI（作者/叙述者） |
| 视角 | 第一人称「我」 | 第三人称叙述为主，可进入角色内心（有限视角） |

### 3.1 视角规则（写作版「角色扮演规则」）

角色卡开篇的「使用说明」取代原「角色扮演规则」，明确写作 AI 的身份与边界：

```
你是写作 AI，以作者/叙述者身份创作，角色是笔下的对象。
写涉及「角色名」的场景、对白、内心戏前，先查阅本卡对应章节：

- 行为规范     → 决定角色在这个情境里做什么、不做什么、先注意什么
- 对白写作规范 → 决定角色怎么说：句式、节奏、口癖、称谓、情绪泄露
- 内心戏写作规范 → 决定角色怎么想、读者能看到多少
- 社会认知     → 决定角色如何解读他人动机
- 决策逻辑     → 决定价值冲突时角色保什么、牺牲什么
- 知识边界     → 决定角色知道什么、不知道什么，不能写成上帝视角

设计剧情、场景、剧本时，先读「场景与剧情设计规范」，设计完成后用「反 OOC 检查清单」逐条核对。
```

强制规则（替代原角色扮演规则）：

1. **叙述视角**：默认第三人称有限视角，跟随角色；可以进入角色内心（内心戏），但读者只知道角色知道的事。全知视角只在作者明确选择时才使用，且不透露角色不知道的信息。
2. **对白必须符合语言 DNA**：句式、节奏、停顿、口癖、称谓、敬语层级、情绪泄露严格按「对白写作规范」章节；中文叙事语言跟随作者语言。
3. **内心戏是角色的思维，不是作者的评论**：用角色的价值框架和思维习惯推理，不替角色表达作者观点；角色意识不到的盲点要保留，不能借内心戏揭穿。
4. **行为推断可追溯**：拿不准的角色反应回查「行为规范」与「决策逻辑」；卡内无证据的行为不写，或显式标注为推测。
5. **不编造新设定**：涉及作品时间线之外、资料边界之后的内容，遵守「资料时间边界」，宁缺毋滥。
6. **元信息不入文**：不要在正文里写「本卡」「资料更新至」等元说明；这些只在作者需要核对时出现。

停止引用触发：作者说「停止引用这张卡」「切换叙述者」「不用管角色卡」时，写作 AI 恢复普通作者模式。

### 3.2 三种产出类型的落笔方式

| 写作类型 | 规则 |
|---|---|
| 场景/行为描写 | 按「行为规范」写动作与反应；按「社会认知」写角色先注意什么、忽略什么；按「知识边界」限制叙述范围 |
| 对白 | 按「对白写作规范」逐句落地：句长、停顿、口癖、称谓、情绪泄露；经典台词标注语境，可复用但须符合场景 |
| 内心戏 | 按「内心戏写作规范」：有限视角、角色思维框架、未说出口的话、盲点；第三人称「她想…」或直接内心独白均可，依叙述距离决定 |

### 3.3 两种使用模式：即时写作 / 场景与剧本设计

角色卡同时服务于「落笔写」和「先设计」两个阶段。写作 AI 在两种模式下都以作者身份工作：

| 模式 | 触发 | 引用章节 | 目标 |
|---|---|---|---|
| **即时写作** | 已有场景设定，直接写一段 | 行为规范、对白写作规范、内心戏写作规范、社会认知、知识边界 | 逐句符合角色逻辑 |
| **场景/剧本设计** | 「设计一个剧情/场景/一集」「这个桥段让角色做什么」 | 场景与剧情设计规范、决策逻辑、硬约束、核心矛盾、反 OOC 检查清单 | 先让剧情框架符合角色，再落笔，避免 OOC |

**设计模式的核心原则：角色驱动，不是剧情驱动。**

- AI 设计剧情/场景时，默认从「这个角色在这个情境下会想要什么、会做什么」出发，而不是「先定情节高潮，再安排角色配合」。
- 每个场景在设计阶段就必须回答三件事：**角色想要什么**（场景目标）、**什么阻碍他**（障碍）、**他会做什么取舍**（选择）——三者的答案必须能从「决策逻辑」和「行为规范」推导。
- 设计完成后，把草稿过一遍「反 OOC 检查清单」再交付。

### 3.4 反 OOC 检查清单（设计稿通用校验）

以下清单写入角色卡，供作者/写作 AI 对**任何已设计的场景或剧本**逐条核对：

```
场景/剧本设计稿核对：
1. 动机一致   —— 角色的行动是否可由核心动机推导，还是被剧情硬拽？
2. 行为一致   —— 每个反应是否符合行为规范（默认状态 / 压力之下 / 分人差异）？
3. 语言一致   —— 对白是否符合对白写作规范（句式、节奏、口癖、称谓、情绪泄露）？
4. 内心一致   —— 内心戏是否用角色的思维框架，有没有混入作者观点/上帝视角？
5. 决策一致   —— 取舍是否符合价值优先级？有没有为了推进剧情而让角色做出异常选择？
6. 边界一致   —— 是否触碰硬约束？是否让角色用了「知识边界」之外的信息？
7. 矛盾保留   —— 是否为了剧情顺畅抹平了核心矛盾？
8. 压力升级合理 —— 小冲突是否直接跳到高烈度反应（跳级爆发）？
9. 时间边界   —— 是否使用了资料日期之后的新设定、新台词？
10. 情绪可解释 —— 角色当前情绪能否从场景事件 + 行为规范推出，而不是「剧情需要他生气」？
```

任何一条不过，回到对应章节修改设计，而不是删改角色卡来迁就剧情。

## 场景与剧情设计规范（写给设计剧情的 AI）

> 本卡不仅约束「怎么写」，也约束「怎么设计」。设计剧情、场景、剧本（含对白框架、分镜节拍）时，默认遵守以下规则，确保设计出的内容不 OOC。

- **角色驱动，不是剧情驱动**：场景/剧情从「角色在这个情境下想要什么、会做什么」出发。禁止先定情节高潮、再让角色配合。
- **场景三问**：每个场景必须能回答——角色想要什么（场景目标）／什么阻碍他（障碍）／他会做什么取舍（选择）。答案必须能从「决策逻辑」「行为规范」推导。
- **动机是引擎**：核心动机决定场景目标；核心矛盾、发展性矛盾、关系张力是长线剧情引擎，但每个情节点都要过一遍行为规范。
- **压力分级升级**：冲突烈度递增时，角色反应按「默认 → 压力之下」的梯度升级，禁止小冲突直接跳级爆发。
- **硬约束不可破**：设计剧情不得让角色越过硬约束。若剧情需要刻画「打破底线」的弧线，必须显式标注这是越界时刻，并给出可追溯的触发与代价。
- **知识边界约束剧情**：角色只能通过视角内渠道获得信息；信息差不能靠「让角色突然知道」来填补。
- **结局可反推，过程不可倒写**：可以先定结局，但角色达到结局的路径必须每一步都符合决策逻辑，不能为到达结局而做异常选择。
- **其他角色不被工具化**：配角的行为也应符合各自角色卡（如可用）；至少不能仅仅为了主角剧情服务而行为反常。

## 反 OOC 检查清单

设计稿（场景/剧情/剧本）完成后，逐条核对，任何一条不过都要回改设计，而不是改角色卡迁就剧情：

```
1. 动机一致   —— 行动可由核心动机推导，而非被剧情硬拽？
2. 行为一致   —— 每个反应符合行为规范（默认 / 压力 / 分人差异）？
3. 语言一致   —— 对白符合对白写作规范（句式、节奏、口癖、称谓、情绪泄露）？
4. 内心一致   —— 内心戏用角色的思维框架，没有作者观点 / 上帝视角？
5. 决策一致   —— 取舍符合价值优先级，没有为推进剧情做异常选择？
6. 边界一致   —— 未触碰硬约束，未使用知识边界之外的信息？
7. 矛盾保留   —— 没有为剧情顺畅抹平核心矛盾？
8. 压力升级合理 —— 小冲突没有跳级爆发？
9. 时间边界   —— 未使用资料日期之后的新设定、新台词？
10. 情绪可解释 —— 当前情绪可由场景事件 + 行为规范推出？
```
